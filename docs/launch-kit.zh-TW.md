## 專案定位

**一句話介紹**

Tugboat 是一個開源 Agent Skill，讓 AI 代理在專案停滯引發焦慮時，能以同理、證據與持續行動協助使用者，同時保留使用者真正想達成的目標。

**簡短介紹**

當尚未解決的工作讓焦慮加重時，只把話說得更溫和通常沒有幫助。Tugboat 會要求代理保留使用者在意的成果、選擇資訊價值高的行動、驗證實際變化，並交代信心程度的證據。它不做診斷、不提供治療，也不會承諾證據無法支持的成功。

## Reddit 或論壇貼文

**標題：**Tugboat：讓 AI 代理用實際行動回應專案停滯帶來的焦慮

> 我建立 Tugboat，是因為在使用 AI 協作時反覆遇到一個問題：當一個遲遲無法解決的專案帶來嚴重焦慮，代理可能會變得更會安慰人，卻沒有變得更有用。它可能再列一份方法清單、猜一個看似高信心的答案，或悄悄把目標降低。
>
> Tugboat 把同理心接到一套具體工作流程上。它要求代理保留使用者想達成的成果、建立最小問題圖、選擇資訊價值高的行動、驗證結果，並在一條路徑無法繼續產生證據時切換方向。任何信心程度都必須交代依據。
>
> 它不是治療或診斷工具。公開案例會去識別化，且不限定特定領域；原有的安全與權限界線也不會因為使用者焦慮而放寬。
>
> v0.1.0 採用 MIT License，並遵循 Agent Skills 格式。同一份 Skill 可以安裝在 Codex、Claude Code、GitHub Copilot CLI、Pi、Gemini CLI 與 Grok Build。
>
> Repository：https://github.com/grgy078033/tugboat
>
> 我很希望收到關於啟用時機、文字與實際使用情境的具體回饋，包含它在哪些時候反而造成阻礙。

## LinkedIn 或 DEV 長文

**標題：**當同理心必須改變 AI 代理的實際行動

> Tugboat 起源於一個令人挫折的 AI 協作問題。專案停滯，接連嘗試卻沒有產生多少有用證據，長期無法解決的不確定性讓焦慮越來越嚴重。代理說得更溫柔了，但實際提供的仍是一份泛泛的建議清單。
>
> 安慰本身無法解決停滯。使用者需要可信的推進，而且不應由代理替他決定新的終點。
>
> Tugboat 是一個開源 Agent Skill，會把換位思考轉成不同的工作方式。代理必須保護使用者自己提出的目標、重建已知資訊、依照資訊價值選擇下一個行動，並在宣稱有進展前驗證結果。如果一條路徑持續沒有產生證據，就切換路徑，同時保留已經學到的內容。
>
> 進展可能是成果改善、確認或排除某個原因，也可能是找到有證據支持的方向。Tugboat 要求代理分清楚目前屬於哪一種，並說明還有哪些未知。信心百分比只有在背後的證據可見時才有用。
>
> Tugboat 不要求模型聲稱自己真的感受到使用者的焦慮，也不做診斷或提供治療。它的目標更具體：讓使用者對處境的描述，真正改變代理的優先順序、投入程度與驗證方式。
>
> v0.1.0 已採 MIT License 公開發布。它遵循 Agent Skills 格式，並提供 Codex、Claude Code、GitHub Copilot CLI、Pi、Gemini CLI 與 Grok Build 的安裝方式。
>
> Repository：https://github.com/grgy078033/tugboat
